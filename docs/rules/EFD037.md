# EFD037: Entities are materialized but only a few columns are read

**Default severity:** Info

**Confidence:** Advisory

**Category:** Performance

EFDoctor reports EFD037 when an EF Core query materializes complete entities into a local, and the method then reads only a small subset of the entity's scalar properties.

A query for entities selects every mapped column. The database reads them, the network transfers them, EF Core materializes them, and the change tracker keeps a snapshot of each entity unless the query is no-tracking. When the code uses two of twenty columns, most of that work is wasted, and a projection lets an index cover the query.

Over-fetching is a cost, not a bug, and whether it matters depends on the table. So EFD037 is advisory and reports at `Info` severity.

## Reported shape

```csharp
// Before: every column of Orders is fetched and tracked, and two are used.
var orders = await db.Orders.Where(o => o.CustomerId == id).ToListAsync();
return orders.Select(o => new OrderSummary(o.Id, o.Total)).ToList();

// After: SQL returns two columns, and nothing is tracked.
return await db.Orders
    .Where(o => o.CustomerId == id)
    .Select(o => new OrderSummary(o.Id, o.Total))
    .ToListAsync();
```

EFD037 reports when all of these hold:

- The query is materialized with `ToList`, `ToArray`, or an awaited `ToListAsync` or `ToArrayAsync`, and the result initializes a local variable.
- The query traces to a `DbSet<T>` or `DbContext.Set<TEntity>()`, returns that entity type, and has no `Include`.
- **Every** use of the local, and of each entity taken from it, is one of the supported reads below.
- The method reads at least one scalar property, at most half of them, and leaves at least four unread.

The finding is located on the materializer call. The evidence names the query origin, the local, the properties the method reads, and the number of scalar properties the entity has. The remediation shows a `Select` with exactly those properties.

## Supported reads

EFD037 has to see everything the method does with the entities. It accepts only these uses of the result local:

| Use | Example |
|---|---|
| A `foreach` over the local | `foreach (var order in orders) { total += order.Total; }` |
| `Select` with a one-parameter selector | `orders.Select(o => new { o.Id, o.Total })` |
| `Any`, `All`, `Count`, `Sum`, `Min`, `Max`, or `Average` with a lambda | `orders.Sum(o => o.Total)` |
| A count with no lambda | `orders.Count`, `orders.Length`, `orders.Any()`, `orders.Count()` |
| An index read followed by a property read | `orders[0].Total` |

Within those, each entity (the loop variable, the lambda parameter, or the indexed value) may only have its scalar properties read. Reads from several uses are combined into one finding.

## Not reported

Anything outside the supported reads means the entity may be needed whole, and EFD037 stays silent:

- **The entities leave the method:** the local or an entity is returned, passed to a method, assigned to a field, property, or another variable, added to a collection, or compared.
- **An entity is modified:** a property is assigned, incremented, or deconstructed into. Loading entities to change and save them is what tracking is for.
- **A navigation, collection, or computed member is used,** such as `order.Customer.Name`, `order.Lines.Count`, or a method call on the entity.
- **Operators that return entities,** such as `orders.Where(…)`, `orders.OrderBy(…)`, or `orders.First()`. Following those results isn't supported yet.
- **A reassigned local,** or a result stored in a field instead of a local.
- **A query that is already shaped:** it projects with `Select`, or loads navigations with `Include` or `ThenInclude`.
- **Single-entity loads,** such as `First`, `Single`, or `Find`.
- **Small entities:** fewer than four scalar properties would be left unread.
- **Sources that aren't a proven EF Core query,** such as an `IEnumerable<T>` parameter.

An inline `ToList().Select(…)` without a local is [EFD004](EFD004.md)'s finding. [EFD005](EFD005.md) may report the same materializer for a different reason, a missing row bound: one finding is about rows, the other about columns.

## How properties are counted

EFDoctor doesn't build the EF Core model, so it approximates the entity's mapped columns from its type. A property counts when it:

- is a public instance auto-property with a getter and a setter, on the entity type or a base type;
- has no `[NotMapped]` attribute;
- has a scalar type: a primitive, `string`, `decimal`, `DateTime`, `DateTimeOffset`, `TimeSpan`, `DateOnly`, `TimeOnly`, `Guid`, an enum, `byte[]`, or a nullable form of one.

Navigations, collections, owned and complex types, and computed properties don't count. Shadow properties and properties ignored only through the fluent API are invisible to this count, which is one reason the rule is advisory and leaves a margin of four unread properties.

## Remediation

Project in the query, before the materializer:

```csharp
var summaries = await db.Orders
    .Where(o => o.CustomerId == id)
    .Select(o => new { o.Id, o.Total })
    .ToListAsync();
```

Keep the entity load when:

- the entities are modified and saved later, by code this rule can't see;
- the table is narrow, so the extra columns cost little;
- the same entities are already tracked by the context, and reusing them avoids a second query.

## Turning the rule off

EFD037 is advisory. To turn it off for a whole repository or directory, use `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.EFD037.severity = none
```

An unsuppressed EFD037 finding still makes a CLI scan exit with code `1`, like every other finding.

## Suppression

```csharp
#pragma warning disable EFD037 // Reviewed: the invoice table is narrow.
var invoices = context.Invoices.Take(50).ToList();
#pragma warning restore EFD037
```

For a single file in `.editorconfig`:

```ini
[InvoiceReport.cs]
# Reviewed: the invoice table is narrow.
dotnet_diagnostic.EFD037.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD037",
    Justification = "The invoice table is narrow.")]
List<int> InvoiceIds(SampleContext context)
{
    var invoices = context.Invoices.Take(50).ToList();
    return invoices.Select(invoice => invoice.Id).ToList();
}
```
