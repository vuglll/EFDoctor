# EFD009: Case transformation on a column prevents an index seek

**Default severity:** Warning

**Confidence:** Medium

**Category:** Performance

EFDoctor reports EFD009 when semantic analysis proves that a predicate in an inline EF Core query applies `ToLower()` or `ToUpper()` to a mapped string column, and then compares the result with a value that doesn't reference the entity.

EF Core translates `customer.Email.ToLower() == email` to `LOWER([Email]) = @email`. Wrapping a column in a function stops the database from seeking an ordinary index on that column. The lookup typically scans instead, and the scan gets slower as the table grows. On SQL Server's default case-insensitive collations, the transformation doesn't even change the result.

## Reported shapes

```csharp
// Equality, in either operand order
context.Customers.Where(customer => customer.Email.ToLower() == email);
context.Customers.Where(customer => email == customer.Email.ToLower());

// A prefix search that could otherwise seek an index
context.Customers.Where(customer => customer.Email.ToUpper().StartsWith(prefix));

// A reference-navigation column in a terminal predicate
context.Orders.FirstOrDefaultAsync(order => order.Customer.Email.ToLower() == email);
```

EFD009 recognizes these comparison forms: `==`, `!=`, static `string.Equals(a, b)`, instance `Equals(value)` with the transformed column on either side, and `StartsWith(value)` with the transformed column as the receiver.

It checks the predicate passed to `Where`, and the predicate forms of `Any`, `All`, `Count`, `LongCount`, `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Last`, `LastOrDefault`, and their EF Core `…Async` versions.

Each transformed column produces one finding, located on the `ToLower()` or `ToUpper()` call. The evidence names:

- the proven `DbSet` origin
- the query operator
- the column path, for example `Order.Customer.Email`
- the transformation method
- the comparison
- the EF Core provider the project references, if any

## Not reported

- **Only the comparison value is transformed**, as in `customer.Email == email.ToLower()`. The value is a parameter, so the column can still use an index.
- **Column-to-column comparisons**, as in `customer.Email.ToLower() == customer.AlternateEmail.ToLower()`. An index seek wasn't possible anyway.
- **`Contains` and `EndsWith`.** They can't seek an index even without a transformation. [EFD023](EFD023.md) reports them, including on a case-transformed column.
- **`StringComparison` overloads**, such as `Equals(value, StringComparison.Ordinal)`. EF Core can't translate them, and [EFD022](EFD022.md) reports them. `string.Compare` is also not reported.
- **`ToLowerInvariant()`, `ToUpperInvariant()`, and culture overloads** such as `ToLower(CultureInfo)`. Whether EF translates them depends on the EF Core version and provider.
- **Computed properties** (expression-bodied or block-bodied getters), because they aren't mapped columns.
- **A transformed column passed to another method**, such as `Matches(customer.Email.ToLower(), email)`.
- **Projections and ordering**, such as `Select(customer => customer.Email.ToLower())` or `OrderBy(customer => customer.Email.ToLower())`.

## Semantic and inline-flow boundaries

The predicate operator must resolve to `System.Linq.Queryable` or `EntityFrameworkQueryableExtensions`, and the transformation must resolve to `string.ToLower()` or `string.ToUpper()` with no arguments. The query must trace directly to `DbSet<T>` or `DbContext.Set<TEntity>()`. The predicate's parameter must be that entity type, so predicates after a `Select` that changes the element type are skipped.

The first version does not report:

- a query stored in an `IQueryable` local whose value isn't statically determined (see [query locals](README.md#query-locals)), an arbitrary `IQueryable<T>` parameter, an in-memory `AsQueryable()` source, or an `IEnumerable<T>` after `AsEnumerable()`
- a transformation inside a nested lambda, such as `customer.Tags.Any(tag => tag.Name.ToLower() == name)`
- the `Where` overload whose predicate also takes an index
- look-alike methods named `ToLower`, `ToUpper`, or `Where` on other types

## Remediation

The remediation depends on the EF Core provider the project references:

- **SQL Server:** the default collations are case-insensitive, so remove the transformation and compare the column directly. For a column with a case-sensitive collation, give the column a case-insensitive collation, or add an indexed computed column that stores the transformed value.
- **PostgreSQL (Npgsql):** text comparisons are case-sensitive by default. Keep the lookup index-friendly with a case-insensitive column type or collation (`citext`, or a nondeterministic collation), `EF.Functions.ILike` with a supporting index, or an expression index on `lower(column)`.
- **No provider detected:** EFD009 gives both kinds of advice.

In every case, normalize the comparison value in C# rather than transforming the column.

## Confidence

EFD009 is medium confidence because EFDoctor can't see database indexes or collations. If the database already has an index on the transformed expression, such as `LOWER(Email)`, or a deliberately case-sensitive collation, the predicate can still be efficient. Suppress the finding with a recorded reason in that case.

## Suppression

```csharp
#pragma warning disable EFD009 // Reviewed: an expression index on LOWER(Email) backs this lookup.
var customers = context.Customers.Where(customer => customer.Email.ToLower() == email);
#pragma warning restore EFD009
```

For a file or directory scope in `.editorconfig`:

```ini
[EditorConfigSuppressed.cs]
# Reviewed: an expression index on LOWER(Email) backs this lookup.
dotnet_diagnostic.EFD009.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD009",
    Justification = "An expression index on LOWER(Email) backs this lookup.")]
IQueryable<Customer> Find(SampleContext context, string email) =>
    context.Customers.Where(customer => customer.Email.ToLower() == email);
```
