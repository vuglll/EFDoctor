# EFD017: Include is ignored by a later non-entity projection

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD017 when semantic analysis proves that an inline EF Core query applies `Include` or `ThenInclude` and then projects with `Queryable.Select` into a result that contains only scalar, value, or newly constructed non-entity data.

A projection determines the data EF Core selects. When the projected result contains no entity on which the include can take effect, EF Core ignores the include: navigation state is not populated in the result, and the include misleads readers into expecting loaded data that isn't there.

## Reported shapes

```csharp
// Scalar projection
var ids = context.Orders
    .Include(order => order.Lines)
    .Select(order => order.Id);

// DTO projection that already reads through the included navigation
var summaries = context.Orders
    .Include(order => order.Customer)
    .Where(order => order.Total > 0)
    .Select(order => new OrderSummary(order.Id, order.Customer.Name));
```

The diagnostic points to the complete `Select` invocation. There is one finding for each projection, however many include paths come before it. The evidence names the proven `DbSet` origin, every resolved include path (for example `Parent.Owner, Parent.Children.Toys`), and the projection shape.

EFD017 reports these result shapes when every projected leaf is definitely non-entity:

- scalar, enum, nullable value, and `string` values, including values computed through a navigation such as `order.Customer.Name` or `parent.Children.Count()`;
- anonymous objects such as `new { parent.Id, parent.Name }`;
- tuples such as `(parent.Id, parent.Name)`;
- object creation and member initializers such as `new OrderSummary(order.Id, order.Customer.Name)` or `new ParentDto { Id = parent.Id }`; and
- conditionals whose branches are both scalar, such as `parent.Active ? 1 : 0`, plus constants and typed `null` members.

Filtered includes (`Include(parent => parent.Children.Where(child => child.Active))`), `ThenInclude` chains, static extension syntax (`Queryable.Select(EntityFrameworkQueryableExtensions.Include(context.Parents, parent => parent.Owner), parent => parent.Id)`), and supported composition between the include and the projection are recognized. Supported composition is `Where`, ordering, `Skip`, `Take`, `Distinct`, tracking modes, `AsSplitQuery`/`AsSingleQuery`, `IgnoreQueryFilters`, `IgnoreAutoIncludes`, and tags.

## Preserved and unsupported shapes

EFD017 does not report when the projection may still carry an entity:

- identity projections: `Select(parent => parent)`;
- wrappers that contain the source entity: `new { Entity = parent }`, `new Wrapper(parent)`, or `(parent.Id, parent)`;
- direct navigation or collection results: `Select(parent => parent.Owner)`, `Select(parent => parent.Children)`, or `new { parent.Id, parent.Children }`; and
- other reference-typed or ambiguous values, such as conditionals returning a navigation, nested collection results like `parent.Children.Select(child => child.Id).ToList()`, `(object)parent.Id`, generic value types that can embed a reference (such as `KeyValuePair<int, Owner>`), and nested member initializers.

Without the application's runtime EF model, EFDoctor can't tell whether an arbitrary reference-typed value is an entity, so it stays silent rather than guess.

## Semantic and inline-flow boundaries

`Include`/`ThenInclude` must resolve to `EntityFrameworkQueryableExtensions`, the projection must resolve to `Queryable.Select` with a single-parameter selector, and the chain must trace to `DbSet<T>` or `DbContext.Set<TEntity>()`. Look-alike methods with the same names, in-memory `AsQueryable()` sources, and arbitrary `IQueryable<T>` parameters are not reported.

EFD017 follows directly connected invocation chains, and query locals whose value is statically determined (see [query locals](../../README.md#query-locals)). It does not report when:

- the query that contains the include is stored in a field, property, parameter, or a conditionally reassigned local and projected later;
- a helper or custom query operator sits between the include and the projection;
- the query is materialized or switched to `Enumerable` (`ToList()`, `AsEnumerable()`) before an in-memory `Select`;
- an earlier `Select` already appears between the include and the projection; or
- the only includes are string-based (`Include("Owner")`), which can't be validated without the runtime model.

If an include selector isn't a plain source-rooted property path, for example a cast, the evidence quotes the include invocation text instead of a path.

## Remediation

- **The projection is all the caller needs:** remove the redundant `Include`/`ThenInclude`. The projection requests every value it references, including data read through a navigation such as `order.Customer.Name`, so nothing is lost.
- **The caller needs populated navigations:** return the entity, or an entity-bearing result, from the query instead of a scalar or DTO shape.

Do not materialize the query before `Select` just to make the include take effect. That loads complete entities client-side, which is the over-fetching pattern EFD004 describes.

## Suppression

If you keep an include on purpose, use standard Roslyn suppression and record the reason.

```csharp
#pragma warning disable EFD017 // Reviewed: the include documents the aggregate boundary.
var ids = context.Orders
    .Include(order => order.Customer)
    .Select(order => order.Id);
#pragma warning restore EFD017
```

For a file or directory scope in `.editorconfig`:

```ini
[EditorConfigSuppressed.cs]
# Reviewed: the include documents the aggregate boundary for readers of this read model.
dotnet_diagnostic.EFD017.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Correctness",
    "EFD017",
    Justification = "The include documents the aggregate boundary.")]
IQueryable<int> LoadIds(SampleContext context) =>
    context.Orders
        .Include(order => order.Customer)
        .Select(order => order.Id);
```
