# EFD038: Bulk operation leaves tracked entities stale

**Default severity:** Warning for high-confidence findings; Info in a build for medium-confidence ones

**Confidence:** High or Medium

**Category:** Correctness

EFDoctor reports EFD038 when a method loads entities with tracking and then runs `ExecuteUpdate` or `ExecuteDelete` on the same entity type through the same `DbContext` instance.

`ExecuteUpdate`, `ExecuteDelete`, and their async forms send one SQL statement and return. They don't touch the change tracker. So entities of that type which the context already tracks keep the values they were loaded with:

- Reading a tracked entity returns the old values.
- `Find`, and any tracking query for the same row, returns the tracked instance, not what is now in the database.
- Modifying a stale entity and calling `SaveChanges` overwrites the bulk update with old values, or throws `DbUpdateConcurrencyException` when the row was deleted.

Nothing fails at the bulk operation itself, and the code looks correct in review.

## Reported shape

```csharp
var product = await db.Products.FindAsync(id);             // tracked

await db.Products
    .Where(p => p.Id == id)
    .ExecuteUpdateAsync(s => s.SetProperty(p => p.Price, newPrice));   // EFD038

var again = await db.Products.FindAsync(id);               // returns the tracked instance
Console.WriteLine(again.Price);                            // old price
```

EFD038 reports the bulk operation when all of these hold:

- **A tracked load.** An earlier statement declares a local and initializes it, after any `await`, with `Find` or `FindAsync`, or with `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Last`, `LastOrDefault`, `ToList`, `ToArray`, or an EF Core async form of one. The query returns the entity type, and has no `AsNoTracking` or `AsNoTrackingWithIdentityResolution`.
- **The same entity type.** The bulk operation's query starts from the `DbSet` of the type that was loaded.
- **The same context instance,** proven by symbol, as in [EFD027](EFD027.md): a local or parameter that is never reassigned, a `this` or static field or auto-property, or `this`.
- **A certain order.** The load is a statement directly inside a block, and the bulk operation is in a later statement of that block. It may be nested in an `if`, a loop, or a `try`.

Each bulk operation gets one finding, located on the bulk-operation call. When several loads qualify, the evidence names the closest one.

## Confidence

| Confidence | When | Severity (CLI) | Severity (build) |
|---|---|---|---|
| High | After the bulk operation, the method references the loaded local, loads the same entity type again from the same context, or calls `SaveChanges`/`SaveChangesAsync` on it after modifying a loaded entity | Warning | `warning` |
| Medium | Nothing after the bulk operation uses the stale state in this method | Warning | `suggestion` |

A medium finding is still real: the entities stay tracked and stale for the rest of the context's lifetime, which in a web request usually means until the request ends. But this method doesn't observe them, so the rule can't show a wrong value.

The evidence says which of the three uses was found, and on which line. A `SaveChanges` with no modified loaded entity doesn't raise the confidence: it writes nothing stale back.

## Not reported

- **No-tracking loads:** the query uses `AsNoTracking` or `AsNoTrackingWithIdentityResolution`.
- **The bulk operation runs first.** A load after it reads current values.
- **A managed tracker.** Anywhere after the load, the method calls `ChangeTracker.Clear()`, `Entry(entity).Reload()` or `ReloadAsync()`, or sets `Entry(entity).State = EntityState.Detached` on the same context.
- **Filters that can't overlap:** the load and the bulk operation each compare the same property with a different constant, such as `s.Name == "A"` and `s.Name == "B"`.
- **Another entity type, or a projection** such as `Select(p => p.Name)`.
- **Contexts that can't be compared:** two different instances, a reassigned context variable, a context returned by a method, or one reached through another object, such as `unitOfWork.Db`.
- **Order that isn't certain:** the load and the bulk operation are in sibling branches, the load is inside a nested block or loop that the bulk operation is not part of, or either is inside a lambda or local function.
- **Loads that don't initialize a local,** such as `db.Products.Find(id)!.Price = 1`, or an assignment to a variable declared earlier.

## Boundaries

EFD038 can't see everything that decides whether an entity is stale:

- **It barely compares the bulk filter with the loaded rows.** Only different constants on the same property are recognized as disjoint. Loading one product by ID and then deleting discontinued products is reported, although the loaded product may be unaffected. This is the case to suppress.
- **It doesn't know the context's default tracking behavior.** A context configured with `QueryTrackingBehavior.NoTracking` doesn't track these loads.
- **It works within one method.** A load in one repository method and a bulk operation in another, on the same scoped context, is the same bug and isn't reported.
- **It doesn't see entities tracked another way,** through `Add`, `Attach`, or navigation loading.

## Remediation

Pick the one that fits:

- **Run the bulk operation first,** then load.
- **Load without tracking,** with `AsNoTracking()`, when the entities are only read before the bulk operation.
- **Clear the tracker** after the bulk operation: `db.ChangeTracker.Clear()`. This detaches everything, so do it when nothing else is pending.
- **Reload or detach the affected entities:** `await db.Entry(product).ReloadAsync()`, or `db.Entry(product).State = EntityState.Detached`.
- **Use a separate context** for the bulk operation, for example from `IDbContextFactory<T>`.

## Suppression

Suppress EFD038 only when the bulk operation can't affect the loaded entities, and record why.

```csharp
var product = await context.Products.FindAsync(id);
#pragma warning disable EFD038 // Reviewed: the cleanup filter can't match the loaded product.
await context.Products.Where(candidate => candidate.Discontinued).ExecuteDeleteAsync();
#pragma warning restore EFD038
```

For a single file in `.editorconfig`:

```ini
[ProductCleanup.cs]
# Reviewed: the cleanup filter can't match the loaded product.
dotnet_diagnostic.EFD038.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Correctness",
    "EFD038",
    Justification = "The cleanup filter can't match the loaded product.")]
async Task<Product?> LoadAndCleanUp(SampleContext context, int id)
{
    var product = await context.Products.FindAsync(id);
    await context.Products.Where(candidate => candidate.Discontinued).ExecuteDeleteAsync();
    return product;
}
```
