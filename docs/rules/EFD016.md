# EFD016: CancellationToken not passed to an EF Core async call

**Default severity:** Info

**Confidence:** Advisory

EFDoctor reports EFD016 when an EF Core async call leaves out its `CancellationToken`, while a `CancellationToken` parameter is in scope. That token might be an ASP.NET Core action's `cancellationToken`, a background service's `stoppingToken`, or a handler's token.

Without the token, cancelling the request or shutting down the host doesn't cancel the database command. The command keeps a connection and the database's resources until it completes, although nothing waits for its result. Under load, or with slow queries, abandoned commands pile up and slow down the requests that are still waiting.

## Reported shapes

```csharp
public async Task<List<Order>> Search(string term, CancellationToken cancellationToken)
{
    // Before: the query ignores cancellation.
    return await db.Orders.Where(o => o.Name.StartsWith(term)).ToListAsync();

    // After: the query is cancelled with the request.
    return await db.Orders.Where(o => o.Name.StartsWith(term)).ToListAsync(cancellationToken);
}
```

EFD016 covers:

- EF Core's async query terminals and bulk operations: `ToListAsync`, `FirstOrDefaultAsync`, `CountAsync`, `AnyAsync`, `ExecuteUpdateAsync`, `ExecuteDeleteAsync`, and the rest;
- `SaveChangesAsync`, including overrides;
- `FindAsync`. `FindAsync(id)` uses the overload without a token. The one with a token is `FindAsync(new object[] { id }, cancellationToken)`.

A token is in scope when it is a parameter of the containing method, or of an enclosing lambda or local function, such as a minimal API handler. The diagnostic points to the call, and the message names the token.

## Boundaries

EFD016 doesn't report:

- a call that passes a token, including an explicit `CancellationToken.None` or `default`, which records a deliberate choice;
- a method with no `CancellationToken` parameter in scope. A token held only in a field, a local, or `HttpContext.RequestAborted` isn't followed;
- synchronous EF Core calls, which EFD010 covers in async code;
- look-alike methods that aren't EF Core's.

## Remediation

- Pass the token in scope: `ToListAsync(cancellationToken)`, `SaveChangesAsync(cancellationToken)`, or `FindAsync(new object[] { key }, cancellationToken)`.
- When an operation must complete even if the caller cancels, such as an audit write, pass `CancellationToken.None` explicitly, so the choice is visible.

## Suppression

```csharp
[SuppressMessage("Reliability", "EFD016", Justification = "The audit write must complete even if the request is aborted.")]
```

To turn the advisory rule off for a project, set `dotnet_diagnostic.EFD016.severity = none` in `.editorconfig`. `#pragma warning disable EFD016` works too.
