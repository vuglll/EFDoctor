# EFD001: SaveChanges executed inside a loop

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD001 when semantic analysis resolves an invocation to an EF Core `DbContext.SaveChanges` or `SaveChangesAsync` overload and that invocation is lexically inside a supported loop body.

Saving per iteration can create repeated database round trips and prevent EF Core from batching a larger unit of work effectively. This is a likely performance risk, not proof that the code is incorrect or that a particular runtime cost was measured.

## Supported loops

- `for`
- `foreach`
- `await foreach`
- `while`
- `do`/`while`

Calls remain in loop scope when nested in ordinary blocks such as `if`, `try`, `using`, switch, or another loop. Calls through custom `DbContext` subclasses and overrides are supported.

## Loops that save once per batch

EFD001 reports a save once per item, not a save once per batch. That batching is
what the remediation recommends. The innermost loop around the save counts as a
batch loop when:

- **it iterates chunks:** a `foreach` whose element is itself a collection, such as
  `foreach (var chunk in ids.Chunk(100))`;
- **its condition declares the page:** `while (pager.ReadNextPage(out var page))`,
  `while (Load() is { Count: > 0 } page)`, or `while ((page = Load()).Count > 0)`;
- **its body loads the page:** a `while`, `do`, or `for` body that loads a collection
  into a local, iterates it with `foreach`, and then saves;
- **it flushes at a threshold:** the save is inside `if (processed >= BatchSize)`
  for a counter incremented in the loop, inside `if (index % 100 == 0)`, or inside
  `if (buffer.Count >= 100)`.

A per-item loop nested inside a batch loop is still reported. So is a save guarded by
an ordinary condition, such as `if (item.IsTransient)`.

One accepted false negative: `if (list.Count > 0)` also looks like a threshold, so a
save it guards is not reported.

## Typical remediation

When the unit of work permits it, update tracked entities in the loop and call `SaveChanges` once afterward. Consider explicit batching for very large sets.

Review before changing code when per-item saves intentionally provide:

- independent transactions;
- immediately required generated keys;
- deliberate partial-failure boundaries; or
- strict consistency requirements.

If one of these applies, retain the code and use a standard Roslyn suppression with a specific justification. Suppression examples are in the repository README.

## First-version limitation

EFD001 does not perform interprocedural analysis. It does not follow a helper method called from a loop, and it stops loop-ancestor inspection at lambda, anonymous-function, local-function, and member boundaries. A loop located inside one of those callable bodies is still analyzed normally.
