# EFD023: Leading-wildcard search on a column cannot seek an index

**Default severity:** Info

**Confidence:** Advisory

**Category:** Performance

EFDoctor reports EFD023 when semantic analysis proves that a predicate in an inline EF Core query searches a mapped string column with a substring, suffix, or leading-wildcard pattern:

- `Contains(value)`
- `EndsWith(value)`
- `EF.Functions.Like(column, pattern)` where the pattern starts with `%` or `_`

EF Core translates these to a pattern that starts with a wildcard, such as `LIKE '%term%'`, or to a function over the column, such as `CHARINDEX`. Neither lets the database seek an ordinary index on the column, so the search typically scans every row, and the cost grows with the table.

Scanning is often fine for small or rarely searched tables, and a full-text or trigram index may already make the search efficient. EFDoctor can't see either, so EFD023 is advisory and reports at `Info` severity.

## Reported shapes

```csharp
// Substring and suffix searches
context.Customers.Where(customer => customer.Name.Contains(term));
context.Customers.Where(customer => customer.Email.EndsWith(domain));

// The same searches on a case-transformed column
context.Customers.Where(customer => customer.Name.ToLower().Contains(term));

// LIKE patterns that provably start with a wildcard
context.Customers.Where(customer => EF.Functions.Like(customer.Name, "%" + term));
context.Customers.Where(customer => EF.Functions.Like(customer.Name, $"%{term}"));
context.Customers.Where(customer => EF.Functions.Like(customer.Name, "_mith"));
```

EFD023 knows a `Like` pattern starts with a wildcard when the pattern is one of these:

- a constant
- a concatenation whose leftmost part is a constant
- an interpolated string whose first part is literal text

Both `Like` overloads are recognized, including the one with an escape character.

EFD023 checks the predicate passed to `Where`, and the predicate forms of `Any`, `All`, `Count`, `LongCount`, `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Last`, `LastOrDefault`, and their EF Core `…Async` versions.

Each search produces one finding, located on the search call. The evidence names:

- the proven `DbSet` origin
- the query operator
- the column path, for example `Order.Customer.Name`
- any `ToLower()`/`ToUpper()` applied to the column
- the search form and why it has a leading wildcard
- the EF Core provider the project references, if any

## Not reported

- **Prefix searches:** `StartsWith(prefix)`, and `Like` patterns such as `prefix + "%"` or `"smith%"`. These can seek an index.
- **`Like` patterns whose first character can't be determined**, such as a variable, a method result, or an interpolated string that starts with a placeholder (`$"{term}%"`).
- **`StringComparison` overloads**, such as `Contains(term, StringComparison.OrdinalIgnoreCase)`. EF Core can't translate them, and [EFD022](EFD022.md) reports them.
- **The `char` overloads**, such as `Contains('x')`.
- **A collection's `Contains(column)`**, such as `names.Contains(customer.Name)`, which translates to an `IN` list.
- **Column-to-column searches**, such as `customer.Name.Contains(customer.Nickname)`.
- **Computed properties** (expression-bodied or block-bodied getters).
- **Searches in projections**, such as `Select(customer => customer.Name.Contains(term))`.

A case transformation compared with `==`, `Equals`, or `StartsWith`, such as `customer.Name.ToLower() == term`, is [EFD009](EFD009.md)'s finding. A case-transformed column searched with `Contains` or `EndsWith` is EFD023's finding. Each shape gets exactly one finding.

## Semantic and inline-flow boundaries

The predicate operator must resolve to `System.Linq.Queryable` or `EntityFrameworkQueryableExtensions`. The search must resolve to `string.Contains(string)`, `string.EndsWith(string)`, or EF Core's `DbFunctionsExtensions.Like`. The query must trace directly to `DbSet<T>` or `DbContext.Set<TEntity>()`, and the predicate's parameter must be that entity type.

The first version does not report:

- a query stored in an `IQueryable` local whose value isn't statically determined (see [query locals](../../README.md#query-locals)), an arbitrary `IQueryable<T>` parameter, an in-memory `AsQueryable()` source, or an `IEnumerable<T>` after `AsEnumerable()`
- a search inside a nested lambda, such as `customer.Tags.Any(tag => tag.Name.Contains(term))`
- predicates after a `Select` that changes the element type
- look-alike methods named `Contains`, `EndsWith`, or `Like` on other types

## Remediation

The remediation depends on the EF Core provider the project references:

- **SQL Server:** for word or phrase search, use a full-text index with `EF.Functions.Contains` or `EF.Functions.FreeText`.
- **PostgreSQL (Npgsql):** a `pg_trgm` GIN trigram index lets `LIKE` and `ILIKE` with leading wildcards use an index. For word or phrase search, use `tsvector` full-text search.
- **No provider detected:** EFD023 lists both options.

Whatever the provider, these may also fit:

- If a prefix search meets the need, use `StartsWith`, which can seek an index.
- For suffix searches, store a reversed or computed column and search it by prefix.
- If a scan is acceptable for the table, or a supporting index already exists, suppress the finding with a recorded reason.

## Turning the rule off

EFD023 is advisory. To turn it off for a whole repository or directory, use `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.EFD023.severity = none
```

An unsuppressed EFD023 finding still makes a scan exit with code `1`, like every other finding.

## Suppression

```csharp
#pragma warning disable EFD023 // Reviewed: the customer table is small and rarely searched.
var customers = context.Customers.Where(customer => customer.Name.Contains(term));
#pragma warning restore EFD023
```

For a single file in `.editorconfig`:

```ini
[EditorConfigSuppressed.cs]
# Reviewed: the customer table is small and rarely searched.
dotnet_diagnostic.EFD023.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD023",
    Justification = "The customer table is small and rarely searched.")]
IQueryable<Customer> Search(SampleContext context, string term) =>
    context.Customers.Where(customer => customer.Name.Contains(term));
```
