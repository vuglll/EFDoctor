# EFD002: Count used only to test existence

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD002 when semantic analysis identifies an EF Core query count whose result is used directly only to decide whether matching rows exist. In these cases, `Any` or `AnyAsync` states the intent and allows the database provider to use an existence query that can stop after the first match.

Counting solely for existence can require the database to process more matching rows. This is a likely performance opportunity, not a claim that every provider scans every row or that a specific speedup is guaranteed.

## Reported forms

For a non-negative count, EFD002 recognizes these equivalent direct comparisons and their operand-reversed forms:

| Intent | Count form | Replacement |
|---|---|---|
| Rows exist | `query.Count() > 0` | `query.Any()` |
| Rows exist | `query.Count() != 0` | `query.Any()` |
| Rows exist | `query.Count() >= 1` | `query.Any()` |
| No rows exist | `query.Count() == 0` | `!query.Any()` |
| No rows exist | `query.Count() <= 0` | `!query.Any()` |
| No rows exist | `query.Count() < 1` | `!query.Any()` |

Compile-time integer constants are treated like the equivalent literal. Parentheses and implicit numeric conversions do not prevent a finding.

Asynchronous queries use the corresponding asynchronous form:

```csharp
// Before
var hasMatches = (await context.Entities.CountAsync(cancellationToken)) > 0;

// After
var hasMatches = await context.Entities.AnyAsync(cancellationToken);
```

Predicate overloads should preserve the predicate:

```csharp
// Before
var hasActive = context.Entities.Count(entity => entity.IsActive) > 0;

// After
var hasActive = context.Entities.Any(entity => entity.IsActive);
```

For an empty-set test, negate the existence operation:

```csharp
// Before
var isEmpty = (await context.Entities.CountAsync()) == 0;

// After
var isEmpty = !await context.Entities.AnyAsync();
```

## Semantic scope

Synchronous EFD002 findings require a resolved `System.Linq.Queryable.Count` call whose source expression can be traced to an EF Core `DbSet`. Direct `DbSet` properties, `DbContext.Set<TEntity>()`, and inline query chains such as `Where(...).Select(...)` are supported.

Asynchronous findings require a resolved EF Core `EntityFrameworkQueryableExtensions.CountAsync` overload. EFDoctor does not report from method-name text alone.

EFD002 does not report:

- `System.Linq.Enumerable.Count` over in-memory collections;
- unrelated or unresolved methods named `Count` or `CountAsync`;
- `LongCount` or collection `Count` properties;
- exact-count checks such as `Count() == 1` or thresholds such as `Count() > 1`;
- a count returned, displayed, or used in arithmetic;
- unsupported relational-pattern syntax such as `Count() is > 0`;
- a synchronous `Queryable.Count` whose source is only known as an arbitrary `IQueryable<T>`.

## First-version limitations

EFD002 analyzes the count and its containing comparison as one expression. It does not use general data-flow or interprocedural analysis. A count stored and compared later is intentionally not reported:

```csharp
var count = context.Entities.Count();
return count > 0; // Not reported in the first version.
```

Likewise, a helper that returns a count is not connected to an existence comparison in its caller. These boundaries favor high-confidence findings over speculative provider or value-flow inference.

## Suppression

Use standard Roslyn suppression and record why the count form is intentional.

For the smallest source region:

```csharp
#pragma warning disable EFD002 // Count retained for provider-specific diagnostics.
var hasRows = context.Entities.Count() > 0;
#pragma warning restore EFD002
```

For a file or directory scope in `.editorconfig`:

```ini
[ProviderDiagnostics.cs]
# Reviewed: the exact count query is retained for provider comparison diagnostics.
dotnet_diagnostic.EFD002.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD002",
    Justification = "Count retained for provider-specific diagnostics.")]
bool UsesIntentionalCount(DbContext context)
{
    return context.Set<Entity>().Count() > 0;
}
```

EFDoctor has no proprietary suppression file.
