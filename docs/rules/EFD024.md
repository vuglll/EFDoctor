# EFD024: Included collection filtered in memory

**Default severity:** Info

**Confidence:** Advisory

EFDoctor reports EFD024 when a query loads a collection navigation in full with `Include`, and the method then only ever uses that collection filtered in memory, such as `blog.Posts.Where(p => p.Published)`.

The query transfers, materializes, and (with tracking) tracks every related row, and the filter throws most of them away. Since EF Core 5, a **filtered include** applies the filter in SQL, so only the rows you use are loaded.

## Reported shapes

```csharp
// Before: every post is loaded, and only the published ones are used.
var blog = await context.Blogs.Include(b => b.Posts).FirstAsync(b => b.Id == id);
var published = blog.Posts.Where(p => p.Published).ToList();

// After: the database filters the posts.
var blog = await context.Blogs
    .Include(b => b.Posts.Where(p => p.Published))
    .FirstAsync(b => b.Id == id);
var published = blog.Posts.ToList();
```

The load can be a single entity (`First`, `Single`, `Last`, … and their async forms) or a list (`ToList`, `ToArray`, … and their async forms). For a list, EFD024 follows `foreach` over it, and the lambdas of `Enumerable` calls on it, such as `blogs.Select(b => b.Posts.Count(p => p.Published))`.

A use counts as filtered when the navigation is the source of `Where`, `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Last`, `LastOrDefault`, `Any`, `All`, `Count`, or `LongCount` with a predicate. The diagnostic points to the `Include`. The evidence counts the filtered uses.

## Boundaries

EFD024 doesn't report:

- a navigation that is also used in full: `blog.Posts.Count`, `foreach (var post in blog.Posts)`, or an operator without a predicate;
- an entity or list that leaves the method, by being returned, passed to a method, or stored, where callers may use the full collection;
- an `Include` that is already filtered, or a reference navigation;
- a query that isn't a proven EF Core query, or one that's materialized somewhere other than a local declaration.

## Remediation

- Move the filter into the `Include`: `Include(b => b.Posts.Where(p => p.Published))`. Filtered includes support `Where`, `OrderBy`, `ThenBy`, `Skip`, and `Take`.
- With tracking, a filtered navigation can still contain entities of that type that the context already tracks from earlier queries. Use `AsNoTracking()`, or a projection, when the method needs exactly the filtered rows.
- Keep the full `Include` when the collection is small.

## Suppression

```csharp
[SuppressMessage("Performance", "EFD024", Justification = "A blog has a handful of posts.")]
```

To turn the advisory rule off for a project, set `dotnet_diagnostic.EFD024.severity = none` in `.editorconfig`. `#pragma warning disable EFD024` works too.
