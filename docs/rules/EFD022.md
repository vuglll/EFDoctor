# EFD022: StringComparison is not translatable in a query predicate

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD022 when a `System.String` method that takes a `System.StringComparison` argument — `Equals`, `StartsWith`, `EndsWith`, `Contains`, `IndexOf`, or the static `string.Equals`/`string.Compare` — is called inside a lambda passed to a `System.Linq.Queryable` operator whose source is a proven EF Core `DbSet`.

EF Core has no SQL translation for the `StringComparison` overloads. Since EF Core 3.0 disabled implicit client evaluation of predicates, such a query does not silently run slowly — it **throws** `InvalidOperationException: The LINQ expression ... could not be translated` when it executes. The code compiles and looks correct, so the failure surfaces only at runtime.

## Reported shapes

```csharp
// Before: throws at runtime — EF Core cannot translate the StringComparison overload.
var matches = context.Customers
    .Where(c => c.Name.Equals(name, StringComparison.OrdinalIgnoreCase))
    .ToList();

// After: a translatable comparison (case sensitivity follows the column collation).
var matches = context.Customers
    .Where(c => c.Name == name)
    .ToList();
```

```csharp
// Also reported: StartsWith/EndsWith/Contains and static string.Equals with StringComparison.
context.Customers.Where(c => c.Name.StartsWith(prefix, StringComparison.Ordinal));
context.Customers.Where(c => string.Equals(c.Name, name, StringComparison.Ordinal));
```

The diagnostic points to the offending string-method call. The evidence names the resolved method, its `StringComparison` argument, and the proven EF origin of the enclosing query.

## Boundaries

The call must resolve to a `System.String` method with a `StringComparison` parameter, and the lambda that contains it must be an argument to a `System.Linq.Queryable` operator whose inline source traces to `DbSet<T>` or `DbContext.Set<TEntity>()`. EFD022 does not report:

- a plain comparison with no `StringComparison` argument (`c.Name == name`, `c.Name.StartsWith(prefix)`), which EF Core translates;
- an in-memory query (`System.Linq.Enumerable` operators over a `List<T>` or after `ToList()`/`AsEnumerable()`), where client evaluation is expected;
- an arbitrary `IQueryable<T>` parameter whose origin is not a proven `DbSet`; or
- a `StringComparison` call outside any query predicate (ordinary client code).

A `StringComparison` call nested inside an in-memory `IEnumerable` operator within a predicate — for example over a navigation via `Enumerable.Any` — is out of scope for this version; the immediate enclosing operator must be a `Queryable` operator.

## Remediation

Use a comparison EF Core can translate:

- a plain `==`, `StartsWith`, `EndsWith`, or `Contains` **without** a `StringComparison` argument — string comparisons then follow the database column's collation;
- if you need case-insensitive matching, configure a case-insensitive collation on the column (or database) rather than a `StringComparison` in the query; or
- if the comparison genuinely must run on the client, materialize first with `AsEnumerable()`/`ToList()` and filter afterward — then suppress EFD022 with a recorded reason.

## Suppression

Use standard Roslyn suppression and record why client evaluation is acceptable.

```csharp
#pragma warning disable EFD022 // Reviewed: this query is materialized and filtered on the client on purpose.
var matches = context.Customers.Where(c => c.Name.Equals(name, StringComparison.Ordinal)).ToList();
#pragma warning restore EFD022
```

For a file or directory scope in `.editorconfig`:

```ini
[EditorConfigSuppressed.cs]
# Reviewed: this query is materialized and filtered on the client on purpose.
dotnet_diagnostic.EFD022.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Correctness",
    "EFD022",
    Justification = "This query is materialized and filtered on the client on purpose.")]
public static IQueryable<Customer> Sample(SampleContext context, string value) =>
    context.Customers.Where(customer => customer.Name.Equals(value, StringComparison.Ordinal));
```
