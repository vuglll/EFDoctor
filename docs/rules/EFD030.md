# EFD030: Query returned after its DbContext is disposed

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD030 when a method returns a deferred EF Core query from inside the `using` scope that disposes the query's `DbContext`. A deferred query is an `IQueryable<T>`, or `AsEnumerable()` or `AsAsyncEnumerable()` over one.

An EF Core query runs only when it is enumerated. Here, the context is disposed as the method returns, so the caller's `ToList()` or `foreach` throws `ObjectDisposedException: Cannot access a disposed context instance`. The method compiles and looks like an ordinary repository method, so the failure surfaces only at the call site, at run time.

## Reported shapes

```csharp
// Before: the context is disposed at the return, before the caller runs the query.
public IQueryable<Order> OpenOrders()
{
    using var db = _factory.CreateDbContext();
    return db.Orders.Where(order => order.Open);
}

// After: materialize while the context is alive.
public async Task<List<Order>> OpenOrdersAsync()
{
    await using var db = await _factory.CreateDbContextAsync();
    return await db.Orders.Where(order => order.Open).ToListAsync();
}
```

Also reported:

- a `using (var db = …) { return db.Orders; }` statement;
- `await using`, including in an async method that returns `Task<IQueryable<T>>`;
- a query held in a local, including one that branches recompose with `query = query.Where(…)`;
- `AsEnumerable()` or `AsAsyncEnumerable()` over the query;
- a context resolved from a service scope that the method disposes:

```csharp
using var scope = _services.CreateScope();
var db = scope.ServiceProvider.GetRequiredService<ShopContext>();
return db.Orders; // disposing the scope disposes the scoped context
```

The diagnostic points to the returned expression. The evidence names the context, how it is disposed, and the query's `DbSet` origin.

## Boundaries

EFD030 doesn't report:

- a **materialized** result, such as `ToList()`, `await ToListAsync()`, `Count()`, or an entity;
- a context that **outlives the method**: an injected field, a parameter, or a local created without `using`;
- a `return` **after** a `using` statement's block ends, or **inside a lambda or local function** declared within the `using` scope;
- an **iterator** method, whose `yield return` runs while the `using` scope is still open;
- a context disposed by an explicit `Dispose()` or in a `finally` block, or one created by a helper method. These are outside this version.

## Remediation

- Materialize the result before returning, for example with `ToList()` or `await ToListAsync()`. Return `List<T>` or `IReadOnlyList<T>`.
- If callers need to compose the query further, let them own the context's lifetime. Inject a scoped `DbContext` into the class, or take the context as a parameter, instead of creating and disposing one in this method.

## Suppression

Suppress only when every caller provably enumerates the query before the method's scope ends, and record why.

```csharp
[SuppressMessage("Reliability", "EFD030", Justification = "Test helper; the caller enumerates inside the scope.")]
public IQueryable<Order> Orders()
{
    using var db = _factory.CreateDbContext();
    return db.Orders;
}
```

`#pragma warning disable EFD030` and `dotnet_diagnostic.EFD030.severity = none` in `.editorconfig` also work.
