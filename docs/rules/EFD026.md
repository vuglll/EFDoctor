# EFD026: Update on an entity the context already tracks

**Default severity:** Info

**Confidence:** Advisory

EFDoctor reports EFD026 when a method calls `Update(entity)` on an entity that it loaded, with tracking, from the same `DbContext` instance.

`Update` exists for *detached* entities. It attaches the entity, and marks **every** property as modified. A tracked entity doesn't need it: the change tracker already knows which properties changed, and `SaveChanges` writes only those. Calling `Update` anyway turns a one-column `UPDATE` into a full-row one. That writes more data, does more trigger and replication work, and overwrites concurrent changes that other writers made to other columns.

## Reported shapes

```csharp
// Before: Update makes SaveChanges write every column.
var order = await context.Orders.FirstAsync(o => o.Id == id);
order.Status = OrderStatus.Shipped;
context.Update(order);
await context.SaveChangesAsync();

// After: SaveChanges writes only Status.
var order = await context.Orders.FirstAsync(o => o.Id == id);
order.Status = OrderStatus.Shipped;
await context.SaveChangesAsync();
```

EFD026 reports `context.Update(entity)`, `context.Update<T>(entity)`, and `context.Orders.Update(entity)`. The entity must come from a load in an earlier statement of the same method: `Find`/`FindAsync`, or `First`, `Single`, `Last`, … and their async forms, over a query without `AsNoTracking` or a projection. The diagnostic points to the `Update` call. The evidence names the load and the context.

## Boundaries

EFD026 doesn't report:

- an entity from a parameter, built from a request or DTO, or loaded with `AsNoTracking()`, which is `Update`'s real use;
- an entity projected with `Select(o => new Order { … })`, which the context doesn't track;
- a load from a different context instance;
- a method that calls `ChangeTracker.Clear()`, assigns `Entry(entity).State`, or reassigns the local between the load and the `Update`;
- `UpdateRange`, or an `Update` inside a lambda.

## Remediation

Remove the `Update` call. `SaveChanges` saves the changes to a tracked entity on its own.

## Suppression

Suppress when every column must be written on purpose, for example for an audit trigger, and record why.

```csharp
[SuppressMessage("Performance", "EFD026", Justification = "An audit trigger needs every column written.")]
```

To turn the advisory rule off for a project, set `dotnet_diagnostic.EFD026.severity = none` in `.editorconfig`. `#pragma warning disable EFD026` works too.
