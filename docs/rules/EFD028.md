# EFD028: Client-only method in a SQL-translated query

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD028 when a method declared in your own source is called inside a filter or ordering of an EF Core query, and the call reads the query's lambda parameter. The lambda must be passed to `Where`, `OrderBy`, `OrderByDescending`, `ThenBy`, or `ThenByDescending`, or to a predicate terminal such as `Any`, `Count`, `FirstOrDefault`, or their async forms. The query must trace to a `DbSet<T>`.

EF Core translates a query lambda to SQL. It knows how to translate members of the framework and of EF Core, and methods mapped as database functions, but not a method of your application. Since EF Core 3.0 turned off implicit client evaluation, such a query **throws** `InvalidOperationException: The LINQ expression ... could not be translated` when it executes. The code compiles and reads naturally, so the failure surfaces only at run time, on the path that runs the query.

## Reported shapes

```csharp
public static bool IsOverdue(Order order) => order.DueUtc < DateTime.UtcNow && order.Status < 3;

// Before: throws at run time. EF Core can't translate IsOverdue.
var overdue = context.Orders.Where(order => OrderRules.IsOverdue(order)).ToList();

// After: the same logic as an expression EF Core can translate.
var now = DateTime.UtcNow;
var overdue = context.Orders.Where(order => order.DueUtc < now && order.Status < 3).ToList();
```

```csharp
// Also reported: an ordering key, an instance or extension method that reads the entity,
// a call nested in an inner lambda, and a predicate terminal.
context.Orders.OrderBy(order => OrderRules.Priority(order.Status));
context.Customers.Where(customer => customer.HasEmail());
context.Orders.Where(order => order.Lines.Any(line => IsDiscounted(line)));
await context.Orders.CountAsync(order => OrderRules.IsOverdue(order));
```

The diagnostic points to the method call. The message names the method and the query operator. The evidence names the resolved method and the proven EF origin of the query.

## Boundaries

EFD028 doesn't report:

- **a call that reads no lambda parameter**, such as `Where(order => order.DueUtc < Cutoff(now))`. EF Core evaluates that call once on the client and sends its result as a query parameter;
- **a method that EF Core or a well-known library can translate:**
  - a method marked `[DbFunction]`, or named in a `HasDbFunction` call in the same project;
  - a static method declared on the `DbContext`, or a method whose body only throws, which are the usual database-function stubs;
  - a method marked `[Projectable]` (EntityFrameworkCore.Projectables), `[InjectLambda]` (NeinLinq), `[Computed]` (DelegateDecompiler), or `[Expandable]` (LinqKit);
- **a projection.** `Select` is not checked in this version, because EF Core may evaluate a final projection on the client;
- **an in-memory query:**
  - `Enumerable` operators over a list;
  - a query after `ToList()` or `AsEnumerable()`;
  - an in-memory `AsQueryable()` source;
- **an `IQueryable<T>` parameter whose origin isn't proven**;
- **a method from a referenced assembly**, including a shared domain library, and a framework method, such as `string.IsNullOrEmpty` or `EF.Functions.Like`;
- **an unmapped computed property**, or a call through a `Func<T, bool>` delegate.

The query may be stored in a local, including one that branches recompose with `query = query.Where(…)` (see [query locals](README.md#query-locals)).

## Remediation

- Inline the method's logic in the lambda as an expression EF Core can translate. Move values that don't depend on the entity, such as the current time, into locals first.
- If the logic belongs in the database, map the method as a [database function](https://learn.microsoft.com/ef/core/querying/user-defined-function-mapping) with `[DbFunction]` or `HasDbFunction`.
- Only when the result is known to be small, materialize first with `ToList()` or `AsEnumerable()`, and apply the method on the client.

## Suppression

Use standard Roslyn suppression when a library you use translates the method, and record which one.

```csharp
#pragma warning disable EFD028 // Reviewed: translated by our query-rewriting interceptor.
var overdue = context.Orders.Where(order => OrderRules.IsOverdue(order)).ToList();
#pragma warning restore EFD028
```

`[SuppressMessage("Correctness", "EFD028", Justification = "...")]` and `dotnet_diagnostic.EFD028.severity = none` in `.editorconfig` also work.
