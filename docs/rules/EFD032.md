# EFD032: Change to an untracked entity is never saved

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD032 when a method loads an entity with `AsNoTracking()` or `AsNoTrackingWithIdentityResolution()`, changes one of its properties, and then calls `SaveChanges` or `SaveChangesAsync` on the same `DbContext`, with nothing in between attaching the entity.

The context doesn't track an entity loaded with `AsNoTracking`, so `SaveChanges` finds no change to it and writes nothing. The method succeeds, and no exception or warning is raised. The update is silently lost.

## Reported shapes

```csharp
// Before: SaveChangesAsync writes nothing, because 'order' isn't tracked.
var order = await db.Orders.AsNoTracking().FirstAsync(o => o.Id == id);
order.Status = OrderStatus.Shipped;
await db.SaveChangesAsync();

// After: load with tracking when you mean to update.
var order = await db.Orders.FirstAsync(o => o.Id == id);
order.Status = OrderStatus.Shipped;
await db.SaveChangesAsync();
```

```csharp
// Also reported: the elements of an untracked list, changed in a foreach.
var orders = db.Orders.AsNoTracking().Where(o => o.Open).ToList();
foreach (var order in orders)
{
    order.Open = false;
}

db.SaveChanges();
```

The load can be `First`, `FirstOrDefault`, `Single`, `SingleOrDefault`, `Last`, or `LastOrDefault`, or one of their awaited async forms. For a list, it can be `ToList` or `ToArray`, or their async forms, iterated by `foreach`. The change can be a simple, compound, null-coalescing, increment, or decrement assignment. The diagnostic points to the first change. The evidence names the load, the context, and the line of the save.

## Boundaries

EFD032 reports only when nothing between the load and the save can attach the entity. Between the two, the entity may only be read or written through its properties, or compared with `null`. A list may only be the `foreach` collection, or have a property such as `Count` read. EFD032 doesn't report:

- when the entity is passed to any method in between, such as `Update`, `Attach`, `Entry`, `Add`, or a helper of yours, or is returned, stored, captured in a lambda, or reassigned;
- a tracked load, including one that calls `AsTracking()` after `AsNoTracking()`;
- a save on another context, or no save after the change;
- a change made in a helper method, or to a navigation's property (`order.Customer.Name = …`);
- a context configured with `UseQueryTrackingBehavior(NoTracking)` but no `AsNoTracking()` in the query. The analyzer can't see that configuration.

The query may be stored in a local whose value is statically determined (see [query locals](README.md#query-locals)). A conditionally composed local isn't followed, because a branch could add `AsTracking()`.

## Remediation

- Remove `AsNoTracking()` from a load that is meant for an update.
- Or call `db.Update(entity)` or `db.Attach(entity)` before changing it. `Attach` followed by the change marks only the changed properties as modified.
- Or replace the load–change–save sequence with `ExecuteUpdate`/`ExecuteUpdateAsync`, which needs no load at all.

## Suppression

Suppress only when something EFDoctor can't see attaches the entity, such as a `SaveChanges` override or an interceptor, and record which.

```csharp
[SuppressMessage("Correctness", "EFD032", Justification = "AuditInterceptor attaches untracked entities.")]
public void Rename(int id, string name) { ... }
```

`#pragma warning disable EFD032` and `dotnet_diagnostic.EFD032.severity = none` in `.editorconfig` also work.
