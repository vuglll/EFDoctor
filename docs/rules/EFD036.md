# EFD036: Query filter on a column without an index

**Default severity:** Info

**Confidence:** Advisory

EFDoctor reports EFD036 when a query filters an entity only on columns that no index or key leads, according to the model snapshot that EF Core migrations maintain in the same project.

Without an index on a filter column, the database has to scan the table to find the matching rows. The model snapshot records every index and key, and the query records every filter. EFD036 joins the two, so you can spot the queries most likely to scan before they reach production. Whether an index helps depends on the table's size, the filter's selectivity, and the write load, so the finding is advisory: evidence to check against the query plan, not a defect.

## Reported shapes

```csharp
// Snapshot: Order has a key on Id and an index on CustomerId.
modelBuilder.Entity("Shop.Order", b =>
{
    b.HasKey("Id");
    b.HasIndex("CustomerId");
});

// Reported: no index leads with Email.
var orders = context.Orders.Where(order => order.Email == email).ToList();

// Not reported: CustomerId leads an index, so the database can seek on it.
var orders = context.Orders.Where(order => order.CustomerId == id && order.Email == email).ToList();
```

EFD036 collects the predicate's filter columns from its top-level `&&` terms:

- equality: `order.Email == email`;
- ranges: `order.CreatedUtc >= since` (also `<`, `<=`, `>`);
- prefix search: `order.Email.StartsWith(prefix)`;
- membership: `numbers.Contains(order.Number)`.

The predicate can be a `Where`, or the predicate of a terminal such as `FirstOrDefault`, `Any`, `Count`, or their async forms. It may be on a query stored in a local, including one that branches compose (see [query locals](README.md#query-locals)). EFD036 reports when none of the filter columns is the first column of an index, primary key, or alternate key of the entity or its base types. The diagnostic points to the first filter column. The evidence lists the filter columns, and the columns that the entity's indexes lead with.

The second column of a composite index doesn't count: an index on `(TenantId, Email)` doesn't let the database seek on `Email` alone.

## Boundaries

EFD036 doesn't report:

- a predicate where any filter column leads an index or key;
- a project without a model snapshot for the entity. That includes a project whose migrations live in a separate assembly, the common "Migrations project" layout;
- an entity whose snapshot indexes can't be read, for example ones built from a helper method;
- terms inside `||`, comparisons between two columns, `bool` columns, navigation paths such as `order.Customer.Email`, and transformed columns such as `order.Email.ToLower()`. EFD009 and EFD023 cover the transformed and leading-wildcard shapes;
- orderings and projections.

EFD036 is reported when analysis of the whole project completes. In some IDEs it appears only with full-solution analysis on.

## Remediation

- Check the query plan for a table or clustered-index scan.
- If one of the filter columns is selective, add an index for it with `HasIndex(o => o.Email)` or `[Index(nameof(Email))]`, generate a migration, and review the SQL it creates. Put the most selective, equality-filtered column first in a composite index.
- Leave it, and suppress, when the table is small, the column has few distinct values, or the index is managed outside EF migrations.

## Suppression

```csharp
[SuppressMessage("Performance", "EFD036", Justification = "Admin-only search over a small table.")]
static List<Order> Search(SampleContext context, string email) => ...;
```

To turn the advisory rule off for a project, set `dotnet_diagnostic.EFD036.severity = none` in `.editorconfig`. `#pragma warning disable EFD036` works too.
