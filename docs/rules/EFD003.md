# EFD003: Foreign key is missing a covering index

**Default severity:** Warning

**Confidence:** High

EFDoctor reports EFD003 when a supported EF Core relational model snapshot contains a foreign key whose dependent properties are not covered by an index, primary key, or alternate key in that model. The supported-provider allow-list is SQL Server and PostgreSQL through Npgsql.

A missing foreign-key index can require the database to perform additional scans or work for joins and referential updates or deletes. EFD003 identifies a likely performance opportunity from model evidence; it does not claim that a measured slowdown or definite defect exists.

## What EFD003 analyzes

EFD003 semantically analyzes generated classes derived from `Microsoft.EntityFrameworkCore.Infrastructure.ModelSnapshot`. The containing project must reference `Microsoft.EntityFrameworkCore.SqlServer` or `Npgsql.EntityFrameworkCore.PostgreSQL`. EFDoctor never constructs the application's `DbContext`, runs the snapshot, applies migrations, or connects to a database.

For each dependent entity, the rule correlates the snapshot's foreign keys with its indexes and keys. A candidate covers a foreign key when the complete ordered foreign-key property list is the candidate's leading prefix:

| Foreign key | Candidate index/key | Result |
|---|---|---|
| `CustomerId` | `CustomerId` | Covered |
| `TenantId, CustomerId` | `TenantId, CustomerId, CreatedAt` | Covered |
| `TenantId, CustomerId` | `CustomerId, TenantId` | EFD003 |
| `CustomerId` | `TenantId, CustomerId` | EFD003 |

Applicable coverage inherited from a base entity also prevents a finding. Matching is entity-specific and property order is significant.

The diagnostic points to the complete `HasForeignKey(...)` builder invocation in the snapshot. Its evidence names the snapshot, dependent entity, ordered foreign-key properties, and detected provider (`SQL Server` or `PostgreSQL (Npgsql)`).

## Deliberate exclusions and limitations

EFD003 does not report from:

- ordinary `OnModelCreating` or helper code that is not an EF Core model snapshot;
- historical migration `Up` or `Down` methods;
- unrelated or unresolved methods with matching names;
- comments, strings, or inactive preprocessor branches;
- projects that reference only a known auto-indexing provider, including MySQL through Pomelo;
- projects with no supported provider or only an unknown relational provider;
- dynamic entity or property metadata that cannot be reconstructed confidently.

The checked-in snapshot can be stale relative to current model configuration. Regenerate or review migrations before treating EFD003 as a statement about the intended model.

EFDoctor sees the EF model, not the deployed database. An equivalent index created manually or managed by a DBA is therefore invisible to this rule. Verify the physical schema and deployment ownership before suppressing the finding.

A separate migrations project must directly reference its supported provider package—`Microsoft.EntityFrameworkCore.SqlServer` or `Npgsql.EntityFrameworkCore.PostgreSQL`—for EFD003 to identify the model. If Pomelo MySQL is also referenced, EFD003 deliberately does not report because MySQL/InnoDB automatically creates an index for a foreign-key constraint. Other providers are ineligible until they are explicitly classified and added to the allow-list, preserving the conservative cross-provider boundary.

## Remediation

Review query and write patterns, then add an index to the EF model when appropriate:

```csharp
modelBuilder.Entity<Order>()
    .HasIndex(order => new { order.TenantId, order.CustomerId });
```

Generate a migration and review the SQL before applying it. An index may reasonably be omitted for a very small table, a write-heavy workload, a deliberate index consolidation decision, or when an equivalent index is managed outside EF migrations.

## Suppression

Use standard Roslyn suppression and record the verified exception.

For the smallest snapshot source region:

```csharp
#pragma warning disable EFD003 // Equivalent index is managed by the DBA and verified during deployment.
entity.HasOne("Customer", null)
    .WithMany()
    .HasForeignKey("CustomerId");
#pragma warning restore EFD003
```

For a file or directory scope in `.editorconfig`:

```ini
[LegacyContextModelSnapshot.cs]
# Reviewed: the equivalent index is owned by the database deployment project.
dotnet_diagnostic.EFD003.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD003",
    Justification = "Equivalent index is managed by the DBA and verified during deployment.")]
sealed class LegacyContextModelSnapshot : ModelSnapshot
{
    // Generated snapshot body.
}
```

EFDoctor has no proprietary suppression file.
