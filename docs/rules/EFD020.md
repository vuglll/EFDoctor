# EFD020: Query is enumerated more than once

**Default severity:** Warning

**Confidence:** Medium

EFDoctor reports EFD020 when a local variable of type `IQueryable<T>`, whose initializer is a proven EF Core query (traced to a `DbSet`), is enumerated two or more times in the same method.

An `IQueryable` is a deferred query, not a result. Every time you enumerate it — a terminal operator like `Count()`/`ToList()`, or a `foreach` — EF Core sends the query to the database again. Reusing the variable reads as if it already holds data, so the extra round trips are easy to miss and multiply under load.

## Reported shapes

```csharp
// Before: two round trips for the same query.
var query = context.Orders.Where(o => o.Total > 0);
var count = query.Count();      // SELECT COUNT(*) ...
var orders = query.ToList();    // SELECT ... (again)

// After: one round trip, then reuse the in-memory list.
var orders = context.Orders.Where(o => o.Total > 0).ToList();
var count = orders.Count;
```

```csharp
// Also reported: an existence guard followed by enumeration re-runs the query.
var query = context.Orders.Where(o => o.Total > 0);
if (query.Any())                // round trip 1
{
    foreach (var order in query) // round trip 2
    {
    }
}
```

The diagnostic points to the query's local declaration and states how many executions were observed.

## What counts as an execution

- a `foreach` over the local; or
- a materializing or aggregating terminal operator whose source is the local — `ToList`/`ToArray`/`ToDictionary`/`ToHashSet`, `Count`/`LongCount`, `Any`/`All`, `First`/`Single`/`Last` (and `*OrDefault`), `Min`/`Max`/`Sum`/`Average`, `Contains`, `ElementAt`, and their `Async` variants.

Non-terminal composition (`Where`, `Select`, `OrderBy`, …) is not an execution — it produces a new query.

These uses are not executions either:

- **A use composed into another query.** For example,
  `context.Items.Where(i => ids.Contains(i.Id))` is inside an expression-tree lambda,
  so EF Core translates `ids` as a subquery of the same SQL statement. A use inside an
  ordinary delegate lambda, such as `list.Select(_ => query.Count())`, runs on the
  client and still counts.
- **A predicate terminal.** `query.Any(x => x.Name == "A")` and
  `query.FirstOrDefault(x => x.Name == "B")` are two different queries over a shared
  base, not a re-execution. Selector terminals such as `query.Sum(x => x.Total)` or
  `query.ToDictionary(x => x.Id)` still count.

Executions in the two arms of the same conditional aren't added together. With
`flag ? await query.ToListAsync() : query.ToList()`, or one execution in each branch of
an `if`/`else`, only one execution runs. EFD020 counts the largest number of executions
that can happen on one path through the method.

## Boundaries

The local's type must implement `IQueryable<T>` and its initializer must trace to a `DbSet`. EFD020 does not report:

- a query executed at most once;
- a materialized result reused many times (`var list = query.ToList();` — `list` is a `List<T>`, not a deferred query);
- a local that is reassigned after its declaration (later executions may run a different query);
- an arbitrary `IQueryable<T>` parameter not proven to originate from a `DbSet`, or an in-memory sequence; or
- an `IQueryable` returned from, or passed into, another method and enumerated there (cross-method flow is out of scope for this version).

## Remediation

Materialize the query once and reuse the result:

```csharp
var orders = context.Orders.Where(o => o.Total > 0).ToList(); // or ToListAsync()
var count = orders.Count;
var any = orders.Count > 0;
foreach (var order in orders) { }
```

If you genuinely need to re-query — for example to observe data that changed between the two reads — that is legitimate; suppress with a recorded reason.

## Suppression

Use standard Roslyn suppression and record why re-execution is acceptable.

```csharp
#pragma warning disable EFD020 // Reviewed: the second enumeration intentionally re-queries after a save.
var query = context.Orders.Where(o => o.Total > 0);
#pragma warning restore EFD020
```

For a file or directory scope in `.editorconfig`:

```ini
[EditorConfigSuppressed.cs]
# Reviewed: the second enumeration intentionally re-queries after a save.
dotnet_diagnostic.EFD020.severity = none
```

Where the Roslyn host supports it:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance",
    "EFD020",
    Justification = "The second enumeration intentionally re-queries after a save.")]
public static int CountThenList(SampleContext context)
{
    var query = context.Orders.Where(o => o.Total > 0);
    return query.Any() ? query.Count() : 0;
}
```
