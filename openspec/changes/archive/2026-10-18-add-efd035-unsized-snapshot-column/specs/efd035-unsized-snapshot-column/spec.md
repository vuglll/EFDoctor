## Purpose

Define detection of SQL Server column types in an EF Core model snapshot that fail or lose data: an indexed unbounded string, and a decimal left at the default precision.

## ADDED Requirements

### Requirement: Detect an index or key on an unbounded string column
EFD035 SHALL analyze model snapshots even though they are generated code. It SHALL report, with high confidence, a property in a model snapshot's `BuildModel` when both of these hold:
- its `Property(...)` chain sets `HasColumnType("nvarchar(max)")` or `HasColumnType("varchar(max)")`, ignoring case;
- the property's name is one of the columns of a `HasIndex`, `HasKey`, or `HasAlternateKey` of the same entity in that snapshot.

#### Scenario: Indexed nvarchar(max)
- **WHEN** a snapshot maps `Email` as `nvarchar(max)`, and declares `b.HasIndex("Email")` on the same entity
- **THEN** EFD035 reports the `Email` property chain with high confidence

#### Scenario: Composite index and key
- **WHEN** an `nvarchar(max)` column is the second column of a composite index, or part of `HasKey`/`HasAlternateKey`
- **THEN** EFD035 reports it with high confidence

#### Scenario: Generated snapshot
- **WHEN** the snapshot file starts with `// <auto-generated />`, as every snapshot EF Core generates does
- **THEN** EFD035 analyzes it, and reports in it as for any other file

#### Scenario: Unindexed or bounded string
- **WHEN** an `nvarchar(max)` column is not part of any index or key, or an indexed string column is `nvarchar(256)`
- **THEN** EFD035 does not report

### Requirement: Detect a decimal left at the default precision
EFD035 SHALL report, with advisory confidence, a `decimal` or `decimal?` property in a model snapshot's `BuildModel` when all of these hold:
- its `Property(...)` chain sets `HasColumnType("decimal(18,2)")`;
- the chain has no `HasPrecision` call;
- if the compilation contains the entity's CLR type, the CLR property has no `PrecisionAttribute`, and no `ColumnAttribute` with a `TypeName`.

#### Scenario: Default decimal precision
- **WHEN** a snapshot maps `b.Property<decimal>("Rate").HasColumnType("decimal(18,2)")` with no `HasPrecision`
- **THEN** EFD035 reports the `Rate` property chain with advisory confidence

#### Scenario: Configured precision
- **WHEN** the chain has `HasPrecision(18, 6)`, the store type is `decimal(19,4)`, or the CLR property has `[Precision(18, 6)]` or `[Column(TypeName = "decimal(18,2)")]`
- **THEN** EFD035 does not report

#### Scenario: Other providers
- **WHEN** a snapshot maps strings as `text` and decimals as `numeric`
- **THEN** EFD035 does not report

### Requirement: Produce actionable EFD035 findings
Each EFD035 finding SHALL have:
- rule title `Unsized column in the model snapshot`;
- `Correctness` category, `Warning` default severity, and the confidence described above;
- documentation key `EFD035`.

The messages SHALL be:
- `'{entity}.{property}' is nvarchar(max), which SQL Server cannot use in an index or key`, for an indexed string;
- `'{entity}.{property}' has no configured precision, so SQL Server stores it as decimal(18,2)`, for a decimal.

Impact and remediation SHALL be specific to each case:
- For an indexed string, the migration fails. Set `HasMaxLength`.
- For a decimal, values beyond two decimals are silently truncated. Set `HasPrecision` or `[Precision]`. Suppress if `decimal(18,2)` is intended and configured with `HasColumnType`.

#### Scenario: Complete structured finding
- **WHEN** EFD035 reports a property
- **THEN** the finding has the title, category, confidence, documentation key, message, evidence, impact, and remediation for its case

### Requirement: Support standard suppression and existing reporting behavior
EFD035 SHALL use standard Roslyn suppression, and flow through the existing CLI, console and JSON output, and exit codes.

#### Scenario: Suppression
- **WHEN** a matching property is covered by `#pragma warning disable EFD035`, or `dotnet_diagnostic.EFD035.severity = none` applies to the snapshot file
- **THEN** the finding is excluded

#### Scenario: Console and JSON reporting
- **WHEN** a CLI scan of the EFD035 fixture project runs in console and JSON modes
- **THEN** both outputs contain only the expected unsuppressed EFD035 findings, with exact locations, JSON schema version `1`, and exit code `1`
